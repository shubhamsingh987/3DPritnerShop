# FORMA — project handoff

Written for a fresh Claude Code session picking up this project after an account switch.
Read this first, then check `git log` / the files it points to for detail. As of this
writing everything described below is **committed** (HEAD = `475fde0 "7th"`, working tree
clean) — nothing is sitting uncommitted at risk.

## What this project is

FORMA — a curated e-commerce catalog of collectible 3D-printed objects (17 products:
props, figures, vases, organizers, etc.). Next.js App Router + TypeScript + Tailwind v4
(CSS-variable theme system) + Prisma/NextAuth (accounts, cart persistence) + Zustand (cart
store) + Framer Motion + GSAP/ScrollTrigger for scroll animations.

**Important:** `AGENTS.md` at the repo root (imported by `CLAUDE.md`) claims this is a
modified Next.js with breaking changes and points to `node_modules/next/dist/docs/`. That
file is regenerated by `next dev` itself — don't remove it, and don't be alarmed by it. In
practice, standard Next.js/React patterns worked throughout this session; I never actually
needed anything from that docs folder.

The dev server runs on `localhost:3000` (start with `npm run dev` if it's not already up —
check `lsof -ti:3000` first).

## Data model — start here

**`lib/constants.ts`** is the single source of truth for the catalog: the `PRODUCTS` array,
the `Product` / `ColorOption` types, and the image-resolution helpers. Read this file first
in a new session — most product-content questions are answered here.

**`lib/pricing.ts`**: price = `(weightInGrams × materialRate + SHIPPING + MARKETING) ×
PROFIT_MULTIPLIER`, rounded to nearest ₹100. `weightInGrams: null` is a real, intentional
state (unverified print — never guess a weight) and `getProductPrice` returns `null`, which
the UI shows as "Price unavailable". Don't fill in a weight to make a price appear.

## The image/background system (the biggest piece of work this session)

The source studio photos in `public/media/products/*.jpg` have **inconsistent baked-in
backgrounds** — some warm-grey (~`230,226,223`), some pure white, some cream. This caused a
string of visual bugs (random-colored product cards, black/white bars in the product-page
gallery, a giant white rectangle in the dark-mode Featured Piece section, etc.) that all
came from the same root cause and were all fixed the same way. There are three image
helpers in `lib/constants.ts`:

- **`productImage(imageId)`** → `/media/products/<id>.jpg` — the raw photo, background and
  all. Only used where the photo's own background is *wanted* as a full-bleed editorial
  backdrop (the hero bubbles no longer use it — they use `productMedia` cutouts).
- **`productThumb(imageId)`** → `/media/products/thumbs/<id>.png` — a background-removed
  RGBA cutout of the same photo, generated with Python/Pillow (corner-sample the backdrop
  color, alpha-mask by color distance with a feathered edge, trim to the subject's bbox).
  Not every image has one — see `THUMB_IMAGE_IDS` in `lib/constants.ts` for the current
  list (~19 ids, covers the 17 base product photos plus the corset's blue variant/detail
  crops). Two close-up detail crops (`hexapod-mug-stand-detail`, `twist-vase-detail`) were
  deliberately **not** processed — their corners run straight into the product with no flat
  backdrop left to key out safely, so automated matting risks eating into real geometry.
- **`productMedia(imageId)`** → cutout if one exists, else falls back to `productImage`.
  **This is what everything except Hero's bubbles should use.**

The processing script itself was written ad hoc in a scratch directory during the session
and was **never committed to the repo** — if more images need this treatment later, you'll
need to recreate it. The parameters that worked well (documented in `productThumb`'s
docstring too): sample an 8×8px patch at each of the 4 corners, average them for the
backdrop color, alpha = clip((max-channel-diff − 75) / (130 − 75), 0, 1), Gaussian-blur the
alpha channel (radius ~1.2) for a soft edge, then crop to the opaque bbox + 12px padding.
Lower thresholds than that let soft cast shadows bleed through as grey smudges on dark
backgrounds — worth knowing if you regenerate any.

**The pattern to follow everywhere:** the container owns the background (`bg-surface-2`,
the theme-aware token — light `#f2f2ef` / dark `#1a1a1d`, see `app/globals.css`), the media
uses `object-contain` (never `cover` for a product photo — it hides the container's
background and can crop real detail), and the image itself has no background of its own.
Never hardcode a per-product or per-theme color to patch this — it's already solved
generically.

## Shared components

- **`components/designs/ProductMediaGallery.tsx`** — the one gallery component every
  product detail page uses (`app/designs/[slug]/page.tsx` builds a generic
  `GalleryMediaItem[]` array from `product.imageId`/`colorOptions`/`galleryImageIds`/
  `demoVideoId` and passes it in). Handles: fixed-size viewport that never resizes
  regardless of media aspect ratio (root-cause fix — both images and video are
  `position: absolute`, so neither contributes intrinsic size to flex/grid ancestors; don't
  reintroduce `width`/`height: auto` sizing on the media elements, that's the bug this was
  built to fix), vertical/horizontal thumbnail rail, prev/next + counter, crossfade
  transition keyed by media *src* (not index — color swaps reuse the same slot index, so
  keying by index silently breaks the transition), hover-zoom on desktop
  (`useHoverCapable()` — **must** start `false` and set the real value in `useEffect`, not
  in `useState`'s lazy initializer, or you get a hydration mismatch on any real desktop
  browser), and a tap-to-zoom fullscreen lightbox for touch. Container background is
  `bg-surface-2` — it was `bg-neutral-950` (hardcoded dark) earlier this session; that was
  the "black bars in light mode" bug.
- **`components/designs/ProductCard.tsx`** — the grid card (used by `/designs` and the
  homepage `Collection.tsx`). `productMedia()` + `object-contain`, `bg-surface-2`, padding.
- **`components/navigation/Navbar.tsx`** — had a real bug fixed this session: the scrolled
  state was hardcoded `bg-black` with text forced white whenever scrolled *or* on the
  homepage, regardless of site theme — so in light mode, scrolling turned the navbar black.
  Fixed: scrolled background is `bg-surface` (theme token), and "force white text" now only
  applies in the one case that actually needs it — at rest on the homepage, transparent
  over the hero video.
- Cart architecture (`lib/cart.ts`, `lib/useCart.ts`, `lib/actions/cart.ts`): guest cart in
  localStorage, account cart in Postgres via Prisma, merged on sign-in. **One SKU per
  slug, no variant system** — `addToCartAction` always re-derives name/imageId/price from
  the canonical catalog record server-side, ignoring whatever the client sent. This is
  intentional (see the comments in `lib/cart.ts`), which is why color selection on the
  product page is preview-only and never reaches the cart/order.

## Homepage sections (`components/home/`)

- `Hero.tsx` — full-bleed background video + `RisingBubbles.tsx`: clear "liquid glass"
  product bubbles that pop in at the bottom, rise, and pop out at the top (CSS animation,
  `.bubble-lane`/`.liquid-glass` in `globals.css`). Uses `productMedia` cutouts; edge
  refraction is an SVG `backdrop-filter` that only renders in Chromium. Replaced the old
  WebGL marble orbit (`OrbitSpheres.tsx`, `lib/marbleTexture.ts` — deleted).
- `FeaturedPiece.tsx` — **removed**; it duplicated one product right above the full grid.
- `Testimonials.tsx` — Material UI cards (`MuiProvider` in `app/layout.tsx`), styled via
  `sx` with the site's CSS variables. Content is **placeholder** — replace with real reviews.
- `Collection.tsx` — thin wrapper around `ProductCard`, untouched.
- `FinalCta.tsx` — **fully redesigned** this session. Was a single full-bleed close-up
  product photo with generic copy ("Own one of 16."). Now: a small still-life built from
  four real product cutouts (corset vase, hexapod coaster, twist vase as a color accent,
  kunai) positioned with absolute percentage layout on a plain `bg-surface` section —
  reuses existing assets, no image generation involved, stays theme-correct automatically
  since it's composited live in CSS rather than baked into one raster image. Reorders above
  the text on mobile (`order-first` / `lg:order-none`) rather than just shrinking. Copy is
  now "Objects worth keeping around." + a supporting line, avoiding startup/AI clichés.

## Working conventions established this session (worth continuing)

- **No image-generation tool is available in this environment.** When asked to "generate"
  new product photos/angles, the right move is real compositing/cropping of existing
  assets (or asking the user for the real file), never a fabricated render — this matters
  for a physical-product catalog where a fake image would misrepresent what's for sale.
- **Verification workflow**: there's a cached Playwright install (found via
  `~/.npm/_npx/<hash>/node_modules/playwright` — locate it with `find ~ -maxdepth 8 -path
  "*/node_modules/playwright/package.json"` if the hash differs) used to drive headless
  Chromium for visual checks — screenshot to `/tmp`, view with the Read tool, clean up
  after. `npx tsc --noEmit -p .` after every change is the type-check gate. There's no
  other test suite in this project.
- Always check `THUMB_IMAGE_IDS` before assuming an imageId has a transparent cutout
  available — falling back to `productImage` for one that doesn't will reintroduce the
  "random background" bug for that specific image.
